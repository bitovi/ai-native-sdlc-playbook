One play: closing the loop on metrics

Stage 6 runs without a person in the path, with an independent confidence gate between steps. The gate is a deterministic check or a second, adversarial reviewing agent. It decides whether work continues or goes to a human.

6

Closing the loop on metrics

A watched metric leaves its normal range. An agent investigates and writes the next intent.md.

Service owner or on-callMonitoring agentControl bands
Traditional

People watch dashboards and respond to alerts. Fixes start when someone notices.

AI-native

A script watches the metric. A breach invokes Claude. People triage the queue and no longer have to start the work.

A control band is a range around a metric's normal level. The script takes the baseline as the mean of the last 30 days of hourly readings. It also computes sigma (σ), the standard deviation. The 1σ band ends at the mean plus one sigma, 2σ at the mean plus two, and so on.

Detection stays deterministic. No model is involved in deciding that a band was breached.

Prerequisites

  • A structured intent.md to restart the loop
  • Claude-accelerated PR reviews
  • Hooks as an action boundary
  • A rollback path in CI/CD, used by the highest autonomy tier

Infrastructure

  • A metrics store the script can query, such as Prometheus or a CI system API
  • Read access to the repo
  • A way to run Claude Code non-interactively in CI, or the Agent SDK for a service that receives webhooks
  1. Service owner or platform engineer picks one metric with a stable rolling baseline, such as CI test failure rate, post-deploy 5xx rate or PR cycle time.
  2. Write the detection script: a rolling mean and sigma, plus rules that catch slow drift as well as spikes. Keep it in version control and unit test it.
  3. Define the response tiers in version-controlled config (bands.yaml). 1σ logs. 2σ diagnoses read-only. 3σ may act, only by opening a PR or triggering a pre-approved runbook.
  4. Choose the trigger: a scheduled workflow, a webhook from existing monitoring, or a cron job. Claude runs stateless, as a non-interactive CI step or an Agent SDK service in a sandbox.
  5. The agent writes its diagnosis as intent.md in the Stage 1 format.
  6. Service owner or on-call triages the queue: fix now, schedule or dismiss. Product-facing findings go to the product owner.
  7. When a fix ships, add an eval for the incident.

Watch it run in the step-through below. The same setup works for other metrics. A 3σ CI failure rate can quarantine a flaky test or open a revert PR. A PR cycle time drift can produce a report for engineering leadership.

Bands live in config

Tier boundaries are enforced from version-controlled config. Permissions and managed settings deny production access.

People approve

A service owner triages and approves findings. Changes go through the normal PR gate. Runbooks the agent may trigger are approved in advance.

Everything is logged

Invocations, findings and triage decisions are timestamped.

Two more ways the loop gets started

Claude on call with Claude Tag

Claude joins the incident channel

Claude Tag is in public beta, currently in Slack. Claude becomes a member of incident channels under its own identity, so each incident gets a first responder.

  • The conversation and what the team knows stay in the channel, and anyone there can guide the response.
  • Through MCP, Claude checks the metric is back at baseline and says so in the thread.
  • It writes the post-mortem to a version-controlled lessons file that later investigations read.
  • Tagged on a ticket, it triages. A small, bounded fix arrives as a PR through the review gate. Anything larger becomes an intent.md for Stage 1.

Key takeaways

  • Start with one metric that has a stable baseline.
  • Detection is a deterministic script. Claude acts only after a band is breached.
  • Tiers set the limits: 1σ logs, 2σ diagnoses read-only, 3σ proposes a PR or a pre-approved runbook.
  • The agent writes the finding as an intent.md. A person decides: fix now, schedule or dismiss.
  • Every shipped fix adds an eval, so repeat incidents fall over time.
